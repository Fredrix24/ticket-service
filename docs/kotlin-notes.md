# Kotlin в проекте: ключевые решения

## 1. Nullable-типы в отчёте (`avgResolutionTime`)
При расчёте среднего времени решения заявки возможна ситуация, когда завершенных (RESOLVED) заявок за период нет. 
Поле `avgResolutionTime` в `data class` объявлено типом `Duration?`. Благодаря этому компилятор Kotlin требует явной обработки этого кейса через `if (resolvedTickets.isEmpty()) null else ...`. 
**Результат:** исключается `NullPointerException` и деление на ноль, а API возвращает `null`, как и прописано в ТЗ.

## 2. `data class` и операции над коллекциями
Модель отчёта `ReportSummary` реализована через `data class`. Это обеспечивает автоматическую генерацию `equals()` и `hashCode()`, что упрощает написание тестов (сравнение объектов целиком без множества ассертов). 
Для группировки по статусам и приоритетам применены идиоматичные методы `groupingBy { ... }.eachCount()`, а для среднего времени — `sumOf { ... }`. В результате код получился коротким, декларативным и читается без громоздких циклов.
